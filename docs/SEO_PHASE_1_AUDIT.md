# Velixon SEO Phase 1 audit

Updated: July 15, 2026
Scope: repository, generated static output, technical SEO, content architecture, UX/conversion, performance, accessibility, analytics, and deployment readiness.

## Executive summary

Velixon has a strong static SEO base: Astro-generated HTML, centralized metadata and business identity, canonical URLs, crawlable navigation, an XML sitemap, robots directives, reusable commercial-page components, structured data, consent-aware analytics hooks, and a Netlify deployment configuration. Before Phase 1 implementation, the historical generated-output baseline contained 75 HTML pages, 73 indexable URLs, and 73 sitemap URLs.

The current local Phase 1 build generates 83 pages and uses one narrow noindex registry, leaving 78 substantive canonical URLs indexable with 78 matching sitemap URLs. The requested AI Integrations, Contractors, Service Businesses, Lehi, three starter resources, and AI Automation ROI Calculator are implemented. Existing technology, industry, guide, comparison, resource, location, and transparent first-party product-study coverage remains indexable rather than being removed from search without evidence. Generated-output and sampled browser QA passed; the remaining release work is production deployment verification, direct form-delivery and oversized-payload testing, a post-deploy sitemap recheck, and field performance monitoring. Search Console data below is a dated, verified property-level snapshot—not a claim that Velixon ranks for a particular keyword.

## Current architecture

- Framework: Astro 6.4.8 with `@astrojs/sitemap` 3.7.3 and TypeScript 6.0.3.
- Rendering: static site generation; there is no server adapter or application hydration framework.
- Routing: Astro file routes under `src/pages/`; data-backed routes use `getStaticPaths()` and typed records under `src/data/seo/`.
- Shared SEO layer: `src/layouts/MainLayout.astro`, `src/lib/schema.ts`, and `src/lib/directory-schema.ts`.
- Shared page systems: `ClusterLanding.astro`, `ServiceLanding.astro`, `ResourceLayout.astro`, `GuidePage.astro`, `DirectoryHub.astro`, `CaseStudyPage.astro`, FAQ sections, breadcrumbs, related-link grids, and CTA sections.
- Styling: project-owned Astro/CSS components with no component-library dependency.
- Images: public static assets with explicit dimensions on generated site images checked by the current templates; no Astro image service is configured.
- Forms: Netlify Forms with built-in sanitization and Akismet filtering, a site honeypot, bounded client inputs, and accessible client-side status handling.
- Analytics: optional Google Analytics 4, loaded only after consent when a measurement ID is configured.
- Deployment: Netlify, publishing `dist/`, Node 22, with redirects, caching, and security headers in `netlify.toml`.

## Historical baseline verification evidence

- Before Phase 1 edits, `npm run audit:seo` passed against the generated baseline.
- Historical baseline result: 75 generated HTML pages, 73 indexable URLs, and 73 sitemap URLs.
- The audit reported unique metadata, canonical URLs, one H1 per page, parseable required JSON-LD, valid internal routes, local image assets, robots directives, and sitemap parity.
- Live HEAD/status checks returned 200 for `/`, `/services/ai-automation/`, `/robots.txt`, and `/sitemap-index.xml`; `/locations/lehi/` and `/resources/what-is-business-process-automation/` returned 404 at the time checked.

## Current Phase 1 verification evidence

- The final `npm run verify` passed after all Phase 1 code, navigation, and indexation adjustments: Astro check reported 90 files with zero errors, warnings, or hints; the production build generated 83 pages; and the SEO audit found 78 indexable URLs with 78 matching sitemap URLs and zero audit warnings.
- The generated audit passed required-route/indexability, unique metadata, canonicals, complete Open Graph and X cards with actual social-image dimensions, one H1, JSON-LD syntax and required page types, internal routes and fragments, image assets and dimensions, robots, manifest icons, IndexNow verification, and sitemap checks.
- Browser QA sampled 11 priority routes at 390px. Each had one H1, a unique/correct title and canonical, `index, follow`, page-appropriate valid JSON-LD, and zero horizontal overflow.
- At 1024px, AI Integrations correctly used the mobile navigation while desktop navigation remained hidden, with zero horizontal overflow. The opened mobile menu filled the viewport; Escape closed it and restored focus to the summary.
- Reduced motion bypassed the intro. The contact form trimmed whitespace-only required values, rejected them, and focused the first-name field.
- The local preview returned 200 for robots and the sitemap index and 404 for an unknown route. No local form-delivery claim is made; production submission, direct oversized POST, host redirects, production 404 behavior, and deployed-body parity remain post-deploy checks.

## Remaining limitations

- The verified Search Console snapshot supplies aggregate property performance, but it does not establish a ranking for any individual keyword. Backlinks, third-party search volume, GA4 results, and lead quality were not inferred.
- Static checks and sampled browser QA do not prove production form delivery, direct malicious-payload handling, complete WCAG conformance, field Core Web Vitals, or deployed-body parity.
- No lint, unit-test, E2E, or Lighthouse scripts are configured, so none of those checks are claimed as passing.
- Search visibility depends on crawling, indexing, content usefulness, competition, authority, and time; technical implementation alone cannot guarantee a first organic result.
